# Saved trace JSON

`block --json` and `call --json` share the `AnnotatedBlock` object. New output has
`schema_version: 2`; missing versions explicitly load as legacy version 1.
`summary --from-json` and `report` accept versions 1 and 2 and reject unknown
versions. `call` is absent/null for blocks and an object with method, SCALE
input/result, state root, proof bytes and optional decoding/oracle data for calls.
This version describes the public trace JSON, independently of the replay artifact
`format_version`.

The root contains block identifiers, optional measured `timing`, runtime spans,
`totals`, ordered `phases`, and optional `execution` (root check, proof size and RPC
counts). Each phase has a kind, label, optional extrinsic index/call/signed flag,
statistics, ordered operations and optional nested `post_inherents`. `wall_time`
is null without observed bounds; its source distinguishes runtime spans from a
storage-only envelope.

Each operation contains sequence, kind (`op`), raw key/child identity, decoded
names, optional value length/timing, duplicate status, and these v2 observations:

- `origin`: `overlay`, `backend_warm`, `backend_cold`, or null/missing (not recorded).
- `proof_bytes_added`: integer marginal recorder growth, or null/missing (not
  recorded). A recorded zero is a measurement; a missing field is never filled
  with zero.

Legacy input keeps these fields as null. Tables display unknown origins in the
`?`/unknown column and absent proof evidence as `n/a`. Partial evidence is marked
`(partial)`. `fixtures/model/pre-e86f740.json` was generated by the actual
5a1963e CLI and is covered by summary/report golden tests.

# Report JSON

Reports also have `schema_version: 2`. They contain successful block count/hashes,
`errors` (`input`, `error`), totals and complete item/phase/hook/extrinsic maps.
Failed inputs do not discard successful inputs; the command emits output and exits
1 if any failed. Duplicate hashes are failed inputs. `phase_order` records the
first observed execution order; JSON object key order carries no phase ordering.

Tally fields are **sums of observed evidence**. Interpret `proof_bytes` together
with `proof_ops_observed`: zero observations means not recorded, even if the sum
is zero. Origin buckets explicitly include unknown reads. Execution proof and
unattributed proof totals are null without execution evidence; phase proof shares
and extrinsic proof distributions are null without the requisite evidence.
Extrinsic proof distributions require complete per-op evidence for every sample;
wall-time distributions require runtime-span bounds for every sample. Cost totals
used for ranking sum the available evidence. Integer sums saturate on overflow.

Extrinsic distributions are exact through 1,024 samples per metric/type. Thereafter
64 logarithmic buckets per power of two (at most 4,097 buckets) bound memory.
Quantiles use bucket lower bounds: value error is at most 1/64 (1.5625%), with no
rank-error claim. Median averages the two middle ranks; p95 uses nearest rank.
JSON includes all groups; `--top` truncates terminal tables, which report omitted
row counts. Extrinsics rank by total proof bytes by default; `--sort-by ops|time`
selects total operation count or unioned storage time. Ties use call names.
